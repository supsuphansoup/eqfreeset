## 모바일 웹 전용 안내

이 문서는 현재 **모바일 웹 전용** MVP를 기준으로 작성되었습니다.[file:1]  
초기에는 모바일과 데스크톱 웹을 모두 고려했으나, 실제 이용 패턴과 구현 우선순위를 반영해 모바일 웹 경험에 집중하도록 범위를 조정했습니다.[file:1]

### 플랫폼 범위

- 지원 플랫폼: 모바일 웹(안드로이드, iOS 주요 브라우저)
- 권장 형태: 홈 화면 설치를 고려한 PWA(Progressive Web App)
- 화면 기준: 320px ~ 414px 폭(아이폰 SE ~ 일반 플러스급 단말)을 1차 타깃으로 설계[file:1]
- 데스크톱 웹: 디자인 및 레이아웃 최적화 범위에서 제외(접속 시 동작은 가능하되, UI 품질 보장은 하지 않음)[file:1]

### 모바일 UX 원칙

- 터치 우선: 모든 핵심 조작(재생/일시정지, A/B 전환, 선택, 도움말 열기/닫기)은 터치 대상 크기 48×48px 이상으로 설계[file:1]
- 단일 화면 집중: 기기 테스트, A/B 비교, 결과 확인은 각각 풀스크린 또는 이에 준하는 단일 뷰 중심으로 구성해 시야 분산을 줄임[file:1]
- 스와이프 제스처: A/B 전환은 좌/우 스와이프 제스처를 기본으로 하고, 동일 기능을 수행하는 버튼도 함께 제공해 제스처 사용이 어려운 경우를 보완[file:1]
- 바텀시트/풀스크린 모달: 모바일에서 모달성 UI는 중앙 작은 팝업 대신 바텀시트 또는 풀스크린 도움 팝업을 사용해 가독성과 조작성 확보[file:1]

### 네비게이션 구조(모바일 기준)

모바일에서는 하단 탭 바를 기본 네비게이션으로 가정합니다.[file:1]

- 홈: 서비스 소개, 가치 제안, “테스트 시작” CTA
- 기기 테스트: A/B 테스트 풀스크린 화면(기기 선택 → 오디오 선택 → 구간 선택 → 테스트 진행 흐름 포함)[file:1]
- 내 결과: 저장된 EQ 결과, 그래프, 요약, 재튜닝 진입점[file:1]
- 후기: 기기별 후기를 카드 리스트 형태로 제공(스와이프/스크롤 중심)[file:1]
- 정보글: EQ 기초 및 테스트 가이드 등 정보글 목록(아코디언/리스트 형태)[file:1]

데스크톱에서 고려했던 상단 탑 내비게이션 메뉴 구조는 모바일에서는 하단 탭과 햄버거 메뉴(부가 설정/정책 등)에 통합하는 것을 원칙으로 합니다.[file:1]

### 반응형 레이아웃 및 테이블 대체

- 테이블 최소화: 좁은 화면에서 가독성이 떨어지는 복잡한 테이블은 가능하면 카드 UI로 대체합니다.[file:1]
- 예시: “지원 기기 목록”은 기기명, 브랜드, 대표 후기 숫자를 포함한 카드 리스트로 표시하고, 탭/필터로 브랜드별 전환을 지원합니다.[file:1]
- 필수 테이블(정책, 메타데이터 등)은 좌우 스크롤 가능한 단순 2~3열 구조로 제한하고, 모바일에서 폰트와 줄 간격을 넉넉히 잡습니다.[file:1]

### 모바일 오디오 UX 및 제약 반영

- autoplay 금지 대응: 첫 “테스트 시작” 버튼 탭 이후 AudioContext를 초기화하고 재생을 시작하도록 설계해 모바일 브라우저의 자동재생 제한을 준수합니다.[file:1]
- 상태 표시: 로딩과 버퍼링 상태를 명확히 보여주며, 짧은 안내 문구로 “첫 재생을 위해 오디오를 준비 중입니다” 등의 메시지를 제공해 사용자 불안을 줄입니다.[file:1]
- 볼륨 제어: 시스템 볼륨은 OS 레벨에 위임하고, 서비스 내에서는 loudness normalization을 통해 공정한 A/B 비교를 보장하는 방향을 유지합니다.[file:1]

### PWA 및 성능 최적화 가이드(모바일 관점)

- viewport 메타 태그:  
  `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` 를 기본으로 사용합니다.[file:1]
- PWA: manifest.json과 Service Worker를 통해 홈 화면 설치, 오프라인 캐싱(테스트 샘플 및 핵심 자산)을 지원합니다.[file:1]
- 성능: 이미지와 오디오 자산은 지연 로딩(lazy loading)을 적용하고, 초기 진입 시 필수 자산만 선로드하여 첫 화면 시간을 최소화합니다.[file:1]

이 섹션을 통해 본 문서의 모든 기능/화면/정책은 모바일 웹 경험을 1순위로 고려해 설계된다는 점을 명시적으로 남깁니다.[file:1]

## 개요

이 문서는 블루투스 이어폰·헤드폰 사용자를 위한 개인화 EQ 웹서비스의 초기 MVP를 정의한다 [file:1].  
서비스는 AutoEq 기반 기기별 기본 보정 데이터를 출발점으로 사용하고, 브라우저 내 A/B 청취 비교를 통해 초보자도 쉽게 개인화된 10‑band EQ를 찾을 수 있도록 설계한다 [file:1].

초기 MVP는 모바일 웹과 데스크톱 웹을 지원하며, 메뉴는 홈, 기기 테스트, 내 결과, 후기, 정보글의 5개로 제한한다 [file:1].  
커뮤니티, 외부 EQ 앱 export, 소셜 기능은 초기 범위에서 제외한다 [file:1].

---

## 제품 목표

핵심 목표는 사용자가 EQ 이론이나 주파수 지식을 몰라도 몇 번의 청취 비교만으로 자신의 기기와 취향에 맞는 사운드를 찾게 만드는 것이다 [file:1].  
AutoEq는 기기별 base EQ의 출발점을 제공하고, 개인화는 pairwise comparison 방식의 A/B 테스트로 구현한다 [file:1].

이 MVP는 “복잡한 EQ 조절 도구”보다 “귀로 고르는 개인화 도구”에 가깝다 [file:1].  
따라서 기술적 정밀성만이 아니라 초보자 친화성, 비교 공정성, 결과 신뢰, 업로드 안전성, 선택 보조 UX까지 함께 고려한다 [file:1].

## 타깃 사용자

주 타깃은 EQ에 익숙하지 않은 초보자 사용자다 [file:1].  
이들은 gain, Q, target curve 같은 개념을 이해하지 못해도 서비스 사용에 문제가 없어야 한다 [file:1].

사용자는 “A가 더 좋다”, “B가 더 좋다”, “비슷하다”처럼 감각 기반 선택만 수행하고, 시스템이 그 선택을 개인화된 EQ 추천으로 변환한다 [file:1].  
이 방식은 직접 점수 입력이나 수동 밴드 조정보다 진입장벽이 낮다 [file:1].

## 핵심 가치 제안

서비스의 핵심 가치는 세 가지다 [file:1].

- 기기별 기본 보정이 자동으로 적용된다 [file:1].
- 사용자는 몇 번의 듣기 비교만으로 개인화된 결과를 얻는다 [file:1].
- 결과는 저장되고 설명되며, 후기와 정보글을 통해 신뢰가 강화된다 [file:1].

또한 A/B 선택 중간에 **선택도움** 기능을 제공해 초보자도 무엇을 들어야 하는지 이해한 상태에서 응답할 수 있게 한다 [file:1].  
맥락형 도움말은 필요한 순간에만 정보를 제공해 인지부하를 줄이는 데 유리하다 [file:1].

## 핵심 화면 UI 명세 (모바일)

아래는 모바일 웹 기준의 최소 UI 구조 정의다.[file:1]  
모든 주요 버튼은 모달(바텀시트 또는 풀스크린) 기반으로 동작하는 것을 전제로 한다.[file:1]

### 1. 시작 화면 (홈)

- 상단
  - 좌측 상단: `홈` 버튼 (로고 또는 아이콘)
  - 우측 상단: `메뉴` 버튼 (햄버거 아이콘, 설정/정책/정보 이동)[file:1]
- 중앙(세로 정렬, 가운데 정렬)
  - `기기 EQ 개인화` 버튼
  - `후기` 버튼
  - `정보글` 버튼  
  각 버튼 탭 시, 해당 기능이 **모달 형식**(바텀시트 또는 풀스크린)으로 열리며, 배경은 반투명 처리된 상태로 유지된다.[file:1]
- 하단
  - 화면 맨 아래 작은 글씨 텍스트 링크 3개를 가로로 배열한다.
    - `이용약관`
    - `개인정보 처리방침`
    - `AutoEq 라이선스`  
  각 링크는 전체 화면을 덮는 정책/라이선스 모달로 열리며, 닫기 버튼으로 홈 화면으로 복귀한다.[file:1]

#### 시작 화면 요약 구조

- 상단 바: 홈 버튼 / 메뉴 버튼
- 중앙 영역: 세로로 정렬된 3개의 메인 CTA 버튼
- 하단 링크: 약관, 개인정보, 라이선스(텍스트 링크, 모달 열림)[file:1]

---

### 2. A/B 테스트 화면

- 상단 영역
  - `오디오 플레이어` 영역
    - 재생/일시정지 버튼
    - 현재 재생 위치 및 전체 길이 표시
    - 필요 시 A/B 상태에 따라 시각적 구분 제공(A 또는 B 표시)[file:1]
- 중간 영역
  - `A/B 선택 버튼` 영역
    - A 선택 버튼
    - 비슷함 선택 버튼(옵션)
    - B 선택 버튼  
    모바일에서 터치하기 쉽게 충분히 큰 버튼으로 가로 또는 세로 배치한다.[file:1]
- 하단 영역
  - `선택팁` 버튼
    - “선택 팁” 또는 “선택 도움” 버튼 1개
    - 탭 시 현재 비교 축에 맞는 설명이 **모달 형식**(바텀시트 또는 풀스크린 팝업)으로 열린다.[file:1]
    - 팝업에는 3~5문장 정도의 짧은 안내와 닫기 버튼을 포함한다.[file:1]

#### A/B 테스트 화면 요약 구조

- 위쪽: 오디오 플레이어
- 가운데: A/B 선택 버튼(선호 선택)
- 아래쪽: 선택팁 버튼(도움 모달 오픈)[file:1]

---

### 3. 결과 화면

- 상단 영역
  - `그래픽 EQ 결과` 이미지 또는 그래프
    - 10‑band EQ 결과를 시 بص각적으로 표시하는 그래프 이미지 또는 캔버스 영역
- 중간 영역
  - 결과 그래프 바로 아래 버튼 2개
    - `후기` 버튼: 이 기기에 대한 후기를 작성하거나 확인하는 모달을 연다.[file:1]
    - `저장` 버튼: 현재 EQ 결과를 계정에 저장하는 확인 모달을 연다.[file:1]
- 하단 영역
  - `다시 테스트` 버튼
    - 전체 화면 하단에 단일 버튼으로 배치한다.
    - 탭 시 동일 기기/오디오로 A/B 테스트를 다시 시작하는 플로우로 이동한다.[file:1]

#### 결과 화면 요약 구조

- 위: 그래픽 EQ 결과 이미지/그래프
- 바로 아래: 후기 / 저장 버튼(나란히 또는 세로)
- 그 아래: 다시 테스트 버튼(재진입용)[file:1]

---

### 모달 동작 공통 규칙

- 모든 “버튼 → 모달” 전환은 뒤로가기 제스처(안드로이드/브라우저 뒤로가기)와 닫기 버튼으로 닫을 수 있어야 한다.[file:1]
- 모달가 열리면 포커스는 모달 내부로 이동하고, 닫으면 원래 버튼으로 돌아온다.[file:1]
- 모달는 바텀시트(하단에서 올라오는 형식) 또는 풀스크린(특히 정책/라이선스/긴 텍스트)에 적합한 형태로 선택한다.[file:1]

## 메뉴 구조

초기 MVP 정보 구조는 아래와 같다 [file:1].

| 메뉴 | 목적 | 핵심 요소 |
| --- | --- | --- |
| 홈 | 서비스 소개와 시작 유도 | 가치 제안, 기기 검색, 사용법 요약, 대표 후기, 대표 정보글 |
| 기기 테스트 | 핵심 개인화 테스트 | 기기 선택, 샘플/업로드 선택, 구간 선택, A/B 테스트, 선택도움 |
| 내 결과 | 저장 결과 재확인 | EQ 그래프, 취향 요약, 재튜닝 버튼, 결과 신뢰도 |
| 후기 | 기기별 검증형 후기 열람 | 기기 필터, 구조화 후기, 검증 배지 |
| 정보글 | 초보자 교육 콘텐츠 | EQ 기초, 테스트 가이드, 음향 설명 글 |

메뉴는 최소화하되, 테스트를 시작하고 결과를 신뢰하게 만드는 데 필요한 정보 구조만 남긴다 [file:1].

## AutoEq 및 라이선스 전략

### AutoEq 사용 원칙

기기별 기본 보정 데이터는 공개 API가 아니라 AutoEq 기반 저장소를 내부 서비스용으로 재가공해서 사용한다 [file:1].  
AutoEq는 다양한 헤드폰/이어폰 모델의 측정 기반 결과와 인덱스를 제공하므로, 초기 100기기 DB의 출발점으로 적합하다 [file:1].

AutoEq는 MIT 라이선스를 사용하며, 상업적 이용과 재가공이 허용된다 [web:17][web:21][web:29].  
다만 배포 시 원 저작자의 저작권 및 라이선스 고지를 포함해야 하므로, 서비스 내 “정보·법적 고지” 섹션에 AutoEq 라이선스 전문과 출처 링크를 명시한다 [web:20][web:24].

### 내부 표준 포맷 변환

서비스에서는 AutoEq 결과를 그대로 노출하지 않고, 내부 표준 포맷으로 변환한다 [file:1].

- 10‑band graphic EQ 포맷
- 모델 alias
- 신뢰도 점수
- base_eq_version(버전 관리)

이를 통해 데이터 업데이트와 품질 관리, 추후 자체 측정 데이터 통합이 쉬워진다 [file:1].

초기 100기기는 대중적인 블루투스 제품 위주로 큐레이션한다 [file:1].

## EQ 구조

MVP는 10‑band graphic EQ로 고정한다 [file:1].  
브라우저 구현은 Web Audio API 기반 필터 체인으로 구성하며, 일반적으로 중간 밴드는 peaking, 저역과 고역의 가장자리 밴드는 shelf를 사용한다 [file:1][web:10].

최종 EQ는 다음 두 요소의 합으로 계산한다 [file:1].

- 기기별 AutoEq 기반 base EQ
- A/B 테스트 결과에 따른 personalization delta

이 구조는 기기 편차와 개인 취향을 분리해 다룰 수 있어 설명성과 유지보수성이 좋다 [file:1].

## 오디오 입력 방식

MVP의 오디오 입력은 두 가지다 [file:1].

### 기본 테스트 샘플

서비스 제공 고정 샘플을 사용한다 [file:1].  
이 샘플은 로열티 프리 고음질 음원을 기반으로 준비하고, 보컬/저음/고음 차이가 잘 드러나는 8~12초 구간으로 구성한다 [file:1].

추천 카테고리:

- 보컬 비교용
- 저음 비교용
- 고음/밝기 비교용
- 종합 밸런스용

기본 샘플은 공통 기준을 만드는 것이므로, 비교 품질과 재현성이 중요하다 [file:1].

### 사용자 업로드 음원

사용자는 자신의 음악 파일을 업로드해 테스트할 수 있다 [file:1].  
업로드 파일은 공개 콘텐츠가 아니라 개인 테스트용 입력값으로만 사용한다 [file:1].

이 기능은 “내가 실제로 듣는 음악으로도 확인하고 싶다”는 니즈를 해결하며, 서비스 만족도를 높일 가능성이 크다 [file:1].

## 업로드 보안 정책

파일 업로드는 OWASP에서도 별도의 보안 치트시트로 다룰 정도로 위험 요소가 많은 기능이다 [file:1].  
초기 MVP라도 defense in depth 원칙을 적용한다 [file:1].

| 항목 | 정책 |
| --- | --- |
| 허용 포맷 | mp3, wav, m4a, flac |
| 최대 용량 | 50MB |
| 업로드 권한 | 로그인 사용자만 |
| 검증 방식 | 확장자, MIME type, magic bytes 모두 검사 |
| 저장 파일명 | UUID로 치환 |
| 저장 위치 | 비공개 object storage(S3 등), 웹루트 외부, direct public access 차단 |
| 공개 URL | 발급하지 않음 (signed URL 미사용, 스트리밍 시 서버 사이드 proxy) |
| 보관 기간 | 세션 종료 후 삭제 또는 최대 24시간 내 배치 삭제 |
| 메타데이터 | 오디오 파일의 ID3/메타데이터는 저장 전 제거 |
| 저작권 동의 | 권리를 가진 파일만 업로드 가능, 위반 시 책임은 업로더에게 있음을 고지 |

또한 서버 측 악성코드 스캔(ClamAV 등)을 통해 악성 파일 업로드를 추가로 방어한다 [file:1][web:23].  
이 정책은 보안, 개인정보, 저작권 리스크를 동시에 줄이기 위한 최소 기준이다 [file:1].

## 업로드 프라이버시 안내

업로드 화면에는 아래 내용을 명확히 노출한다 [file:1].

- 업로드 파일은 개인 테스트용으로만 사용됩니다.
- 파일은 공개되지 않습니다.
- 파일은 일정 시간 후 자동 삭제됩니다.
- 권리를 가진 오디오만 업로드할 수 있습니다.

이 안내는 사용자의 불안을 줄이고, 추후 저작권·개인정보 분쟁을 줄이는 역할을 한다 [file:1].

## 업로드 음원 자동 구간 추천

사용자 업로드 음원은 파일 전체를 그대로 테스트에 사용하지 않는다 [file:1].  
시스템이 오디오를 여러 구간으로 나눈 뒤, 주파수 분포를 분석해 EQ 차이가 잘 드러나는 대표 구간을 추천한다 [file:1].

추천 카테고리:

- 저음 비교 추천 구간
- 보컬 비교 추천 구간
- 고음 비교 추천 구간

이 방식은 사용자가 직접 파형과 주파수 대역을 이해하지 않아도, 테스트에 적합한 구간을 쉽게 선택하게 돕는다 [file:1].

## 자동 추천 실패 fallback

자동 추천은 편리하지만 항상 정확하지 않을 수 있으므로 fallback이 필수다 [file:1].

- 자동 추천 구간 3개 제공
- 각 구간은 미리듣기 가능
- 사용자는 “직접 구간 선택” 가능
- 직접 선택은 시작점만 지정하고 길이는 10초로 고정
- 분석 실패 시 곡 중간 10초를 임시 fallback으로 제공

이 구조는 자동 분석이 실패하더라도 테스트 경험이 끊기지 않게 한다 [file:1].

## A/B 테스트 구조

개인화 테스트는 pairwise comparison 기반으로 설계한다 [file:1].  
사용자는 두 개의 EQ 결과를 번갈아 듣고 더 선호하는 쪽을 고르는 방식으로 자신의 취향을 드러낸다 [file:1].

첫 세션의 기본 테스트 구조:

| 단계 | 회차 | 목적 |
| --- | ---: | --- |
| 방향성 탐색 | 1~3회 | 큰 차이로 취향 방향 파악 |
| 미세 조정 | 4~6회 | 세부 성향 수렴 |
| 최종 검증 | 7회 | 최종안과 대체안 비교 |
| 조기 종료 | 5회 이후 | 사용자가 빠르게 종료 가능 |
| 연장 | 8~9회 | 확신이 낮을 때만 추가 |

기본값은 7회이며, 최소 5회, 최대 9회 범위로 운영한다 [file:1].

### 세션 수렴 및 조기 종료 조건

- 동일 축에서 연속 3회 이상 같은 방향 선택 시 수렴으로 간주 가능
- “비슷함” 비율이 60% 이상이면서 응답 시간이 매우 짧은 경우, 수렴 실패로 판단하고 재테스트 권장
- 신뢰도 점수가 일정 기준(예: 0.4 이하)일 때 “다시 테스트하기”를 상단에 강조 노출

## A/B 선택도움 기능

핵심 동작:

- 버튼 클릭 시 설명 팝업 오픈

- 팝업을 닫으면 즉시 테스트 화면으로 복귀

이 기능은 선택 자체를 대신하지 않고, “무엇을 들어야 하는지”를 짧게 안내하는 보조 장치다 [file:1].

## 접근성 기준 (WCAG 2.2 반영)

팝업 기반 도움 기능과 오디오 플레이어는 접근성을 함께 고려해야 한다 [file:1][web:11][web:23].

## loudness 정규화 기준 및 구현

A/B 테스트의 공정성을 위해 loudness normalization 기준을 고정한다 [file:1].  
AES 및 ITU‑R BS.1770 계열 권고는 일관된 loudness 관리가 중요하다고 설명한다 [file:1][web:28][web:30].

MVP 기준:

- 기준 loudness: -16 LUFS
- true peak ceiling: -1 dBTP
- EQ 적용 후 자동 preamp 감쇠
- 테스트 중 사용자 볼륨 조절 비활성화

구현 방향:

- Web Audio API 기반으로 ITU‑R BS.1770 계열 알고리즘을 적용한 loudness 측정 라이브러리 검토(또는 서버 측 배치 전처리) [web:22][web:25].
- 프리셋 샘플 파일은 사전 오프라인 처리로 -16 LUFS에 맞춰 normalization 후 제공.
- 사용자 업로드 음원은 클라이언트/서버에서 짧은 구간의 loudness를 측정해 gain 값을 계산, 재생 시 동일 기준으로 맞춘다.

이 기준은 더 큰 소리가 더 좋게 들리는 착시를 줄이고, A/B 비교의 공정성을 확보하기 위한 핵심 장치다 [file:1][web:28].

- 한 줄 가치 제안: “내 기기에 맞는 EQ를 몇 번의 비교만으로 찾기”
- 기기 검색 CTA
- 사용법 3단계 요약
- 대표 후기 일부 노출
- 대표 정보글 일부 노출

홈에서는 기술적 복잡성을 최소화하고, “쉽다”는 인상을 강화하는 것이 중요하다 [file:1].

---

## 기기 테스트 화면

기기 테스트는 MVP의 핵심 화면이다 [file:1].  
전체 흐름:

1. 기기 선택  
2. 테스트 오디오 선택 (기본 샘플 또는 업로드 음원)  
3. 추천 구간 선택 또는 직접 시작점 선택  
4. A/B 7회 테스트 진행(수렴/조기 종료 조건 반영)  
5. 필요 시 선택도움 버튼으로 가이드 확인  
6. 결과 저장  

초보자 UX를 위해 테스트 전면에는 슬라이더를 노출하지 않고, 청취와 선택에 집중하도록 구성한다 [file:1].

---

## 내 결과 화면

내 결과는 사용자가 저장한 EQ 결과를 다시 확인하고, 필요 시 빠르게 재튜닝하는 공간이다 [file:1].

핵심 요소:

- 기기명
- 테스트 날짜
- 최종 EQ 그래프
- 원본 대비 변화 요약
- 사운드 취향 요약
- 빠른 재튜닝 버튼
- 결과 신뢰도 표시

결과는 단순 데이터가 아니라 “다시 쓸 수 있는 개인 프리셋”처럼 보여야 한다 [file:1].

---

## 결과 재현 메타데이터

결과의 설명성과 재현성을 위해 아래 메타데이터를 저장한다 [file:1].

| 필드 | 설명 |
| --- | --- |
| device_id | 테스트 기기 |
| base_eq_version | 사용한 AutoEq base profile 버전 |
| personalization_delta | 개인화 델타 값 |
| test_audio_type | 기본 샘플 또는 업로드 |
| selected_segment_start | 사용 구간 시작 시점 |
| segment_length | 구간 길이, 기본 10초 |
| response_log | A/B 응답 이력 |
| session_confidence_score | 테스트 신뢰도 |
| engine_version | 추천 엔진 버전 |
| created_at | 저장 시점 |

이 정보는 결과 복원, 디버깅, 추천 품질 개선에 필요하다 [file:1].

---

## 세션 신뢰도 점수

모든 테스트 결과를 동일한 품질로 취급하지 않기 위해 내부 신뢰도 점수를 계산한다 [file:1].  
추천 입력 변수:

- 각 비교 구간 청취 시간
- A/B 전환 횟수
- 응답 시간
- 재청취 여부
- “비슷함” 선택 비율
- 최종 결과 저장 여부

결과는 “높음 / 보통 / 낮음” 3단계로 표현하고, 낮을 경우 재테스트를 권장한다 [file:1].  
신뢰도와 재테스트/만족도 변화를 추적해 알고리즘 개선에 활용한다.

---

## 후기 시스템

후기는 공개 커뮤니티가 아니라 검증형 익명 후기 구조로 운영한다 [file:1].

| 항목 | 정책 |
| --- | --- |
| 공개 표시명 | 익명 게스트 |
| 내부 식별 | 계정 + 테스트 완료 세션과 연결 |
| 작성 조건 | 테스트 완료 + 결과 저장 |
| 작성 수 | 기기당 1개, 수정만 가능 |
| 신뢰 장치 | “검증된 테스트 후기” 배지 |
| 운영 장치 | 신고 가능, 운영자 숨김 가능 |

후기는 만족도, 저음/보컬/고음 변화 체감, 자유 코멘트 등 구조화 필드를 포함한다 [file:1].

---

## 정보글 섹션

정보글은 초보자 교육과 신뢰 형성을 위한 콘텐츠 영역이다 [file:1].  
초기 정보글 주제:

- EQ란 무엇인가
- 저음/중음/고음의 차이
- A/B 테스트 잘하는 법
- 블루투스 음질 기초
- 내 기기에 맞는 EQ 찾는 법
- 고음 피로감 줄이는 법

정보글은 홈, 테스트 전, 결과 후에 적절히 연결 배치해 실제로 읽히게 만든다 [file:1].

## 정책 및 운영

초기 MVP에도 UGC와 업로드가 있으므로 운영 정책은 필수다 [file:1].

필수 정책:

- 후기 신고/숨김/삭제 정책
- 업로드 파일 삭제 정책(최대 보관 기간, 백업 삭제 포함)
- 이용약관 및 개인정보 처리방침
- 반복 위반 사용자 제한 정책

DMCA/유사 제도에 따른 takedown 절차를 간단히 정리해 법적 리스크를 줄인다 [web:24].

## 최종 정의

이 MVP는 다음과 같이 정의할 수 있다 [file:1].

> AutoEq 기반 100개 기기 보정 데이터를 출발점으로, 기본 테스트 샘플과 사용자 업로드 음원의 자동 구간 추천을 활용한 브라우저 내 A/B 청취 비교를 통해 초보자도 쉽게 개인화된 10‑band EQ를 찾게 하고, A/B 선택 과정에서는 선택도움 버튼과 팝업 설명으로 청취 포인트를 안내하며, loudness 정규화와 업로드 보안·저작권 정책으로 비교 공정성과 안전성을 확보하고, 결과 저장·검증형 익명 후기·초보자용 정보글로 신뢰를 만드는 모바일·데스크톱 웹 서비스다.
